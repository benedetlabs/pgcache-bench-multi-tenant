# Multi-Version PgCache Verification Results

> 🇧🇷 **[Versão em português](README-pt.md)**

This directory contains benchmark verification runs comparing new releases of **PgCache**:
- [**PgCache 0.6.3**](0.6.3/README.md)
- [**PgCache 0.6.4**](0.6.4/README.md)
- [**PgCache 0.7.0**](0.7.0/README.md)

All tests were executed in the multi-tenant SaaS workload (500k orders, 2M order items, 200 tenants, 8 statements per dashboard query) using the repository's dynamic warmup (`warm_until_settled`) protocol.

## 2. Key Observations

1. **Query Cacheability & Key-Space Expansion (up to 1,000 tenants)**:
   Every query generated by the eight-statement multi-tenant dashboard reached a **100.0% hit ratio** after warming across all versions up to 500 tenants. At 1,000 tenants in version 0.7.0, the hit ratio held at **99.7%** with 5 warm-up passes, demonstrating exceptional cache retention even under a 5× expanded key-space.

2. **Throughput Scaling**:
   Versions **0.6.3** and **0.6.4** exhibit nearly identical high-throughput profiles under the 200-tenant workload. Version **0.7.0** was evaluated across an expanded 1,000-tenant dataset, maintaining consistent speedups across all concurrency tiers.

3. **PgCache 0.7.0 Profile**:
   Version **0.7.0** successfully passed all compatibility and cache tests. In single-machine Docker Desktop testing with 1,000 tenants, concurrent writes introduce higher CPU utilization for background CDC replication compared to 0.6.3/0.6.4. Official multi-node Kubernetes execution (where PgCache and PostgreSQL origin run on distinct physical nodes) will provide clean isolation for 0.7.0.
